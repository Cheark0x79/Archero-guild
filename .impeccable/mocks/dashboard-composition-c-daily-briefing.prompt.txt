Use case: ui-mockup
Asset type: high-fidelity desktop web dashboard composition probe, 1536x1024 landscape
Primary request: Design composition C for an Archero 2 guild operations web dashboard called “Archero Guild”. This is a real application surface, not a poster or cinematic scene.
Structure in exact order: an ultra-compact dark icon-and-label left navigation rail about 190px; a slim top header; first viewport organized as a daily briefing split 60/40. On the left, one large “Today at a glance” field uses a vertical weekly rhythm from Monday through Sunday, with today clearly highlighted and rows for roster, donations, and boss participation; on the right, a strong stacked “Boss today” panel with restrained Fire Dragon portrait, damage progress, participation, and time remaining. Immediately below, a thin status/freshness band. The next fold contains two wide equal chart panels side by side, with a third boss-damage chart continuing below, avoiding a wall of KPI cards. For Admin state, reserve a clearly identifiable but non-dominant top-right “Needs attention 4” indicator; no action buttons in the main Viewer content.
Navigation text: “Archero Guild”, “Dashboard”, “Members”, “Boss”, role label “Viewer”.
Real UI text: “Today at a glance”, “Boss today”, “Needs attention 4”, “Members 36/40”, “Boss participation 36/40”, “Weekly donations”, “Median power”, “Guild boss damage”, “Last update”, “TEST DATA”.
Visual world: sober guild operations command center with controlled Archero game identity. Light cool-gray main canvas, near-black blue-slate navigation, one cyan accent, amber only for attention, red only for urgency. Crisp workhorse humanist sans, dense but calm, strong numeric hierarchy, thin separators, minimal elevation, modest 6–8px corners. The weekly cadence is the signature visual system, not generic dashboard card soup.
Charts: accessible clean line charts with exactly seven weekday points and clear labels.
Interaction cues: range segmented controls, clear active navigation, subtle route links, no mutation controls for Viewer.
Constraints: English only; explicitly show “TEST DATA”; desktop web app; realistic semantic UI; no glassmorphism, no neon, no gradients, no oversized marketing headline, no mobile frame, no browser chrome, no watermark. Core text must be legible; other microcopy can be neutral lines.
